## 零一万物 Yi API 提供什么

零一万物的 API 平台（`platform.lingyiwanwu.com`）目前提供两个模型：

| 模型 | 适用场景 | 价格（总 token） |
|------|---------|----------------|
| **Yi-Lightning** | 通用对话、推理、编程——智能路由至 DeepSeek-V3 / Qwen3.5 / Yi-Lightning | ¥0.99/百万总 token |
| **Yi-Vision-v2** | 视觉理解——路由至 Qwen2.5-VL-72B 或 Yi-Vision-V2 | ¥6.00/百万总 token |

两个模型均采用 **输入+输出合并计费**——没有独立的输入和输出费率。无论 token 是用于提示还是生成，您每使用一百万个 token 只需支付 ¥0.99。

智能路由机制是关键创新。当您向 Yi-Lightning 发送请求时，零一万物的路由层会评估请求特征（领域、复杂度、语言、token 预算），并在以下模型中做出选择：

- **DeepSeek-V3** —— 最适合复杂推理、数学和代码生成
- **Qwen3.5-30B-A3B** —— 最适合中文任务和通用知识
- **Yi-Lightning（零一万物专有）** —— 最适合双语对话和均衡性能

路由是非确定性的——您无法固定到某个特定底层模型。这既是特性（简化决策），也是限制（无法控制模型）。

## API 接口：标准 OpenAI 兼容端点

Yi API 100% 兼容 OpenAI。基础 URL 为 `https://api.lingyiwanwu.com/v1`，`/v1/chat/completions` 端点接受标准的 OpenAI 请求体。支持流式传输、JSON 模式和函数调用。

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://api.lingyiwanwu.com/v1",
    api_key="YOUR_YI_API_KEY"
)

completion = client.chat.completions.create(
    model="yi-lightning",  # 或 "yi-vision-v2" 用于视觉任务
    messages=[{"role": "user", "content": "用三句话解释智能路由的概念。"}],
    max_tokens=512
)

print(completion.choices[0].message.content)
```

对于已在使用 OpenAI Python SDK 的团队，迁移只需一行改动：替换 `base_url` 和 `api_key`。无需重写 SDK，无需重构请求体。

API 还支持：
- **流式传输**（`stream=True`）用于实时 token 传输
- **函数调用**用于工具使用工作流
- **JSON 模式**通过 `response_format={"type": "json_object"}`

## 优点与缺点

**优点**

- ✅ **¥0.99/百万总 token** — 中国前沿级别回复中最便宜的 API 价格之一
- ✅ **智能路由** — 自动为每次请求选择 DeepSeek-V3、Qwen3.5 或 Yi-Lightning
- ✅ **100% OpenAI 兼容** — 零 SDK 迁移成本
- ✅ **合并计费** — 无需分别追踪输入和输出，统一费率
- ✅ **国内可用** — ICP 备案、支付宝/微信支付、大陆直连
- ✅ **李开复博士创立** — 强大的研发背景和开源贡献
- ✅ **支持流式、函数调用、JSON 模式**

**缺点**

- ❌ **仅 2 个 API 模型** — Yi-Lightning + Yi-Vision-v2，无法直接访问 Llama、Qwen 或其他开源模型
- ❌ **智能路由非确定性** — 无法固定到 DeepSeek-V3 或控制哪个模型回答
- ❌ **合并计费不透明** — 无法判断支付 ¥0.99 是在使用便宜的 DeepSeek-V3 推理还是昂贵的 Yi-Lightning 计算
- ❌ **无初始免费额度** — 首次调用必须充值
- ❌ **英文支持较弱** — 文档和社区主要以中文为主
- ❌ **无模型级 SLA** — 路由导致单个模型的延迟和质量存在差异

## 常见问题

**问：Yi-Lightning 能让我选择使用哪个底层模型吗？**
答：不能。智能路由系统会自动为每次请求选择 DeepSeek-V3、Qwen3.5-30B-A3B 或 Yi-Lightning 之一。没有参数可以固定到特定模型。如果您需要确定性模型选择，请直接使用 DeepSeek 或使用 FreeModel 这类聚合器。

**问："合并计费"在实践中意味着什么？**
答：零一万物按总 token 计费——输入 token 加输出 token 的总和。提示和补全没有不同的费率。每百万总 token 统一 ¥0.99。这简化了成本追踪，但无法分别优化提示和生成的成本。

**问：能否在中国境外使用零一万物 Yi？**
答：可以，API 在全球均可访问，但平台针对中国用户优化。英文文档有限，非中国账户的客户支持响应速度可能较慢。通过支付宝/微信支付的人民币支付需要中国支付方式。

**问：Yi-Lightning 相比直接使用 DeepSeek 速度如何？**
答：零一万物不公布每个模型的延迟基准。由于路由在推理前增加了一个决策层，预计首 token 时间比直接调用 DeepSeek-V3 略高。实际使用中，大多数用户报告的典型聊天查询响应时间在 2 秒以内。

**问：Yi-Lightning 是否适合生产环境？**
答：适合对模型选择非确定性可接受的工作负载。对于需要特定模型行为（例如，数学题始终使用 DeepSeek-V3）的场景，路由抽象是一个隐患。如果您需要固定模型访问的同时享受零一万物价格，请考虑 FreeModel 作为多提供商聚合器。
